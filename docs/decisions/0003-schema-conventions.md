# 0003: Schema conventions

**Status:** Accepted
**Date:** 2026-09-27

These rules apply to every table added from here on, across all 21 tables in the ERD.

## Naming

Tables and columns are `snake_case`, matching the ERD (`app_user`, `ticket_id`, `created_at`). This is enforced automatically by `EFCore.NamingConventions` (see [`0001-implementation-stack`](0001-implementation-stack.md)), not by hand-naming every column in C#.

## Time columns

Every time column is `timestamptz`, never `timestamp` without a timezone. In C#, this means `DateTimeOffset`, which the Npgsql provider maps to `timestamptz` by default.

## `created_at` / `updated_at`

- `created_at` defaults to `now()` at insert and is never updated after.
- `updated_at` defaults to `now()` at insert and is set by the application on every update, through an EF Core `SaveChanges` interceptor added when the first entities land (ticket 02+). No database trigger, to keep migrations plain DDL.

## Identity columns

Primary key type follows the ERD, by table volume and role:

- `bigint` identity for high-volume transactional tables (`incident`, `ticket`, `resolution`, `audit_log`, `incident_status_history`, and similar).
- `int` identity for reference/configuration tables (`location`, `category`, `asset`, `service_team`, and similar).
- `smallint` identity for small enumerated lookup tables (`role`, `team_role`, `priority_target`, and similar).
- `uuid` for `app_user`, since user IDs are referenced from client-side code and external systems where a sequential integer would leak signup order.

All integer identities use Postgres-native `GENERATED BY DEFAULT AS IDENTITY` (EF Core Npgsql's `UseIdentityByDefaultColumn()`), not `serial`.

## Migration immutability

A merged migration file is never edited. A correction to an already-merged migration arrives as a new migration that alters or reverses the earlier one. Editing a merged migration desyncs any database that already applied it from one that has not.
