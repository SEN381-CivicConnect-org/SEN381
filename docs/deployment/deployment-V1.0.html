Deployment & Operability

PED v2.0 §6.1 (ASR-04) and §6.4. How CivicConnect stays cost-constrained, portable and container-deployable, and how restore-drill and deployment evidence is recorded here.

Why this is architecturally significant

The scope constraints Cost row says "free or low-cost services must be preferred when possible, and potential operational costs and platform capabilities must be known". RSK-01, the project's main risk, is caused by "unanticipated operational costs or exceeding free-tier resource limitations", mitigated by documenting "resource limits for Docker containerisation deployments early", with contingency to "migrate the chosen backend to an alternative low-cost hosting provider". FEC-02 requires logging, monitoring, health checks and failure detection before staging and production, deferring only the tool choice.

Measurable expectation

  • Given the application is a container image with all environment-specific values in environment variables (NFR-01), when it is redeployed to a different low-cost host, it starts and serves requests with no source-code change.
  • Given the running application, when an operator or hosting probe queries the health endpoint, it reports within a bounded time whether the application and its database are healthy (FEC-02).

Design commitments

Stateless single deployable

No in-memory sessions, no server affinity, no reliance on host-local files. Changing provider is then a redeploy, not a rewrite. A Docker container holds everything needed to run the application and runs on laptops, data-centre machines and clouds alike — why RSK-01 names Docker.

Container plus external configuration

The container makes the runtime portable; environment variables make the behaviour portable. The twelve-factor approach keeps configuration in environment variables, separate from code. NFR-01 covers secrets; the same mechanism is proposed for every value that varies by environment, such as the database host and provider limits.

Observability as a seam

FEC-02 defers the tooling, not the obligation. A health endpoint and a single logging abstraction are committed now, so a later tool choice is only a configuration change, not a redesign. OWASP says logs should record "when, where, who and what", and that passwords, tokens and session identifiers "should usually not be recorded directly in the logs" (OWASP, 2026). This links to ASR-06's access-controlled publication design.

Cost applies to the database too

Cheap application hosting with an always-on replicated database would break the same constraint. One answer covers both tiers: accept bounded downtime and protect data with backups — see "Bottlenecks, SPOF and scalability" in docs/data-persistence/persistence-integrity-and-scaling-V1.0.html.

Docker containerisation

Docker packages the API, Blazor client, and PostgreSQL database into immutable images, giving environment parity between local development, automated testing pipelines and staging (see docs/decisions/technology-stack-V1.0.html for the full ADR-004 rationale). Environment variables passed into the containers decouple secrets and environment-specific configuration from source code, satisfying NFR-01 and the repository secrets rule.

Restore-drill and deployment evidence

NFR-03 requires backups to be verified by a restore drill every milestone: restoring into a clean PostgreSQL instance, passing the integration test suite within a four-hour recovery time objective, and committing a drill record with the elapsed time to this folder. No drill has been recorded yet at the time of this baseline.
