Access Patterns & Index Justification

PED v2.0 §6.3.4. Each capability is broken down into the query it implies. Frequency is measured against the volume assumptions in ASM-07 (30 submissions per working day, 12 service staff, 250 requesters). Selectivity is the fraction of the table that the predicate keeps. An index appears only when a named query pattern needs it — the PostgreSQL manual says indexes "seldom or never used in queries should be removed", and that every index "adds overhead to data manipulation operations" (The PostgreSQL Global Development Group, 2026).

ID Access Pattern Query Frequency Index
AP-01 Render the submission form (active categories, active location tree) Two small scans over 200 rows or fewer About 30 a day plus page loads category_active_idx, location_parent_idx, location_root_name_uq (partial, active rows only)
AP-02 "My requests", newest first WHERE reporter_id = ? ORDER BY submitted_at DESC LIMIT 20 High, every reporter session ticket_reporter_submitted_idx (reporter_id, submitted_at DESC)
AP-03 Idempotent replay check WHERE reporter_id = ? AND idempotency_key = ? Once per submission, including retries The primary key of submission_request, no extra index
AP-04 Staff queue (open incidents for my team, by priority then age) WHERE assigned_team_id = ? AND status IN (open) ORDER BY priority, opened_at The most frequent read in the system incident_team_queue_idx (assigned_team_id, priority, opened_at) WHERE status IN (...), partial because the predicate skips the growing pile of closed incidents
AP-05 "My work" (what this technician holds) WHERE assignee_id = ? AND status IN ('ASSIGNED','IN_PROGRESS','ON_HOLD') High incident_assignee_open_idx (assignee_id) WHERE status IN (...)
AP-06 Incident detail (child reports) WHERE incident_id = ? Per detail view ticket_incident_idx (incident_id)
AP-07 Dashboard by status over a window WHERE status = ? AND opened_at >= ?, GROUP BY status Low (a handful of managers) incident_status_opened_idx (status, opened_at DESC)
AP-07b Overdue list WHERE status IN (open) AND due_at < now() ORDER BY due_at Low, but managers rely on it incident_overdue_idx (due_at) WHERE status IN (...)
AP-07c Analysis by category GROUP BY category_id over a date window Low incident_category_opened_idx (category_id, opened_at DESC)
AP-08 Team membership and supervisor lookup WHERE user_id = ? AND left_at IS NULL Every authorisation check that is not cached team_member_user_idx (user_id) WHERE left_at IS NULL
AP-09 Incident timeline WHERE incident_id = ? ORDER BY changed_at Per detail view status_history_incident_idx (incident_id, changed_at), incident_note_incident_idx (incident_id, created_at)
AP-10 Replacements by asset over a period WHERE asset_id IS NOT NULL AND resolved_at >= ? Monthly resolution_asset_idx (asset_id, resolved_at DESC) WHERE asset_id IS NOT NULL, asset_location_idx
AP-11 Subscriber fan-out through the merge chain WHERE COALESCE(root_incident_id, incident_id) = ? Per status change incident_root_idx (root_incident_id) WHERE root_incident_id IS NOT NULL, plus the incident_subscription primary key prefix
AP-11b "What am I subscribed to" WHERE reporter_id = ? Per reporter session incident_subscription_reporter_idx (reporter_id)
AP-12 Unread notification bell WHERE recipient_id = ? AND read_at IS NULL Every page load notification_unread_idx (recipient_id, created_at DESC) WHERE read_at IS NULL, the best fit for a partial index in the schema
AP-13 This incident's audit trail WHERE incident_id = ? ORDER BY occurred_at DESC Low audit_incident_idx (incident_id, occurred_at DESC) WHERE incident_id IS NOT NULL
AP-14 "What did this actor do" and generic entity lookup WHERE actor_id = ?, or WHERE entity_type = ? AND entity_id = ? Rare, but it is how investigations start audit_actor_idx, audit_entity_idx
AP-15 Submit (cluster or create) INSERT ... ON CONFLICT (category_id, location_id) WHERE status IN (open) 30 a day, in bursts incident_one_open_per_scope_uq, an invariant that doubles as the lookup index
AP-16 Claim, transition, override, resolve UPDATE incident ... WHERE incident_id = ? AND version = ? About 5 per incident Primary key
AP-17 Login WHERE email = ? Per session app_user_email_uq — citext makes the match case-insensitive, so no lower(email) expression index is needed
