Baseline Version: 2.0 (Milestone 4 Final Delivery) | Scope Governance & Controlled Change Log

Controlled Scope Governance

In accordance with SEN381 Master Project Brief §2.6, changes to the baseline must follow formal change control rather than informal drift. Every approved change from Milestone 1 to Milestone 4 was evaluated against ten impact areas, implemented under peer review, verified with automated tests, and logged below.

1. Standard Change Control Lifecycle

  1. Change Request
  2. Impact Analysis
  3. Decision
  4. Authorisation
  5. Implementation
  6. Verification
  7. Baseline Update

2. Mandatory Impact Assessment Areas

Every change proposal is rigorously evaluated across ten distinct engineering dimensions:

  • Requirements & Acceptance Criteria: Traceability impacts on the RTM.
  • Architecture & Design: Invariants, coupling, and modular cohesion.
  • User Interface & IA: Portal navigation and responsive usability.
  • Data & Persistence: Forward-only EF Core migrations and constraints.
  • API / Interface Contract: OpenAPI spec stability and backward compatibility.
  • Security & POPIA Privacy: Least-privilege access, encryption, and data retention.
  • Scope, Schedule, Cost & Resources: Team bandwidth and the ≤ $25/mo budget.
  • Quality, Testing & Regression: Test suite execution and non-functional targets.
  • Deployment & Operations: Docker parity, disaster recovery RTO, and health probes.
  • Risks & Technical Debt: Risk register updates and mitigation strategies.
